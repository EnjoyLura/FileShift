# FileShift 开发工作流

> **版本**：v1.0  
> **原则**：步骤解耦、优先级驱动、每步可验证、由易到难  

---

## 开发原则

### 1. 步骤解耦规范

每个步骤必须满足以下要求：

| 规范 | 说明 |
|------|------|
| **独立可测试** | 每步完成后有明确的验证方式，不依赖后续步骤 |
| **输入/输出明确** | 每步开始前需确认前置条件，完成后产出明确的交付物 |
| **接口契约先行** | 步骤间通过 API 契约（接口定义）解耦，内部实现可自由调整 |
| **回滚友好** | 每步完成后提交 Git commit，出问题可快速回退 |
| **文档同步** | 每步完成后更新对应的代码注释和接口文档 |

### 2. 优先级定义

| 等级 | 含义 | 说明 |
|------|------|------|
| P0 | 必须 | MVP 核心功能，没有则产品无法运行 |
| P1 | 重要 | 显著提升产品价值，第二个版本必须包含 |
| P2 | 锦上添花 | 提升竞争力，可后续迭代 |

### 3. 难度定义

| 等级 | 含义 | 预估时间 |
|------|------|---------|
| 简单 | 常规 CRUD，有成熟方案参考 | 0.5-1 天 |
| 中等 | 需要一定调研，涉及多个模块协作 | 1-3 天 |
| 较难 | 需要深入学习，涉及复杂逻辑或第三方集成 | 3-5 天 |
| 困难 | 需要大量调研，架构设计或性能优化 | 5-10 天 |

### 4. Git 分支策略

```
main              ← 生产环境，只接受 release 合并
  └── develop     ← 开发主线
       ├── feature/step-01-init          ← 每个步骤一个分支
       ├── feature/step-02-database
       ├── feature/step-03-auth
       └── ...
```

每完成一个步骤：`feature/step-xx` → 合并至 `develop` → 验证通过 → 删除特性分支

**目标**：搭建 Monorepo 项目骨架，配置开发工具链，确保团队开发环境一致。

**前置条件**：无

**难度**：中等 | **预估时间**：2-3天

**具体任务**：

| 序号 | 任务 | 说明 |
|------|------|------|
| 0.1 | 初始化 pnpm Monorepo | 创建根目录，配置 `pnpm-workspace.yaml` |
| 0.2 | 创建 `packages/shared` | 共享类型定义包，定义 User、Task、Tool 等核心类型 |
| 0.3 | 创建 `packages/server` | 使用 Vite 或 tsup 搭建 TypeScript Node.js 项目 |
| 0.4 | 创建 `packages/client` | 使用 `npm create vite@latest` 创建 React + TS 项目 |
| 0.5 | 配置 ESLint + Prettier | 统一代码风格，配置 `.eslintrc` 和 `.prettierrc` |
| 0.6 | 配置 TypeScript | 根目录 `tsconfig.base.json`，各包继承 |
| 0.7 | 配置 `.env` 管理 | 使用 `dotenv`，创建 `.env.example` |
| 0.8 | 初始化 Git 仓库 | 配置 `.gitignore`，首次提交 |
| 0.9 | 编写开发环境启动脚本 | `dev` 命令一键启动前后端 |

**交付物**：
- 可运行的 Monorepo 项目骨架
- `pnpm dev` 可同时启动前后端开发服务器
- 前后端能各自返回 "Hello World"

**验收标准**：
```bash
# 验证命令

pnpm --filter @fileshift/server dev   # 后端启动，访问 /api/health 返回 200
```

**完成标记**：`git commit -m "feat: project initialization and engineering setup"`
